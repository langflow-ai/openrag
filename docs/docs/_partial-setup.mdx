The first time you install BomaRAG, the terminal session issues a series of prompts to guide you through the initial configuration.

If BomaRAG detects an existing BomaRAG `.env` file, you might need to select the **Reconfigure** option in the terminal to access the configuration settings.

1. Enter an administrator password for the OpenSearch service.

   This password is required, and a secure password is automatically generated if you don't provide one manually.

2. Enter an administrator password for the Langflow service.

   This password is recommended but optional.
   If the Langflow password is empty, the Langflow server starts without authentication enabled. For more information, see [Langflow settings](/reference/configuration#langflow-settings).

3. At the **AI providers** prompt, you can either enter your model provider credentials now, or press <kbd>Enter</kbd> to configure these options later during application onboarding.

   There is no material difference between providing these values now or during the [application onboarding process](#application-onboarding).
   If you provide a credential now, it can be populated automatically during the application onboarding process if you enable the **Use environment API key** option.

   BomaRAG's core functionality requires access to language and embedding models.
   By default, BomaRAG uses OpenAI models.
   If you aren't sure which models or providers to use, you must provide an OpenAI API key to use BomaRAG's default model configuration.

4. At the **Langfuse tracing** prompt, enter <kbd>Y</kbd> to enable the [Langflow integration with Langfuse](https://docs.langflow.org/integrations-langfuse); otherwise, enter <kbd>N</kbd>.
If you enter <kbd>Y</kbd>, provide the following Langfuse credentials:

   * **Langfuse Secret Key**: A secret key for your Langfuse project.
   * **Langfuse Public Key**: A public key for your Langfuse project.
   * **Langfuse Host**: Required for self-hosted Langfuse deployments. Leave empty for Langfuse Cloud.

5. At the **Documents path** prompt, accept the default [local documents path](/ingestion-configure#set-the-local-documents-path), or provide a path to a directory where you want BomaRAG to look for documents to ingest into your [knowledge base](/knowledge).

6. At the **Cloud connectors and advanced settings** prompt, enter <kbd>Y</kbd> if you want to configure any of the following additional settings; otherwise, enter <kbd>N</kbd>.

   :::info
   You must configure advanced settings if you want to enable either OAuth mode or cloud storage connectors during initial set up:

   * **OAuth mode**: Controls document ownership and access in your BomaRAG [OpenSearch knowledge base](/knowledge).
   Without OAuth mode, there is no differentiation between users; all users that access your BomaRAG instance can access and manage all uploaded documents.
   * **Cloud storage connectors**: Enables ingestion of documents from external storage services.

   You can also [configure these connectors](/knowledge-connectors) later.
   :::

   * **OAuth mode and cloud storage connectors**: To configure one or more of these connectors, do the following:

      1. Register BomaRAG as an OAuth application in your cloud provider, and then obtain the app's OAuth credentials, such as a client ID and secret key. To enable multiple connectors, you must register an app and generate credentials for each provider.

      2. In your BomaRAG terminal session, enter the relevant [OAuth credentials](/reference/configuration#oauth-and-cloud-storage-connector-settings) for the cloud connector prompts:

         <PartialOAuthCredentials />

         The credentials can be populated automatically if BomaRAG detects these credentials in an [BomaRAG `.env` file](/reference/configuration) at `~/.bomarag/tui`.

      3. Register the redirect URIs shown in the terminal in your OAuth apps.

         The redirect URIs are used for the cloud storage connector webhooks. For Google, the redirect URIs are also used to redirect users back to BomaRAG after they sign in.

   * **Webhook Base URL**: If you entered OAuth credentials, you can set the base address for your OAuth connector endpoints. If set, the OAuth connector webhook URLs are constructed as `WEBHOOK_BASE_URL/connectors/${provider}/webhook`. This option is required to enable automatic ingestion from cloud storage.

   * **OpenSearch Data Path**: Use the default path, or specify the path where you want BomaRAG to create your OpenSearch index.

   * **Langflow Public URL** : Sets the base address to access the Langflow web interface where users interact with the Langflow editor in a browser. You must set this value if you want to run Langflow on a non-default port (`7860`)

7. At the `Start services now?` prompt, press <kbd>Y</kbd> to start the BomaRAG services.

   This process can take some time while BomaRAG pulls and runs the container images.
   If all services start successfully, the terminal prints a confirmation message:

   ```text
   Services are running.
   ```

   :::tip BomaRAG .env file
   Your configuration and credentials are stored in the [BomaRAG `.env` file](/reference/configuration) at `~/.bomarag/tui`.
   If you modified any credentials that were pulled from an existing `.env` file, those values are updated in the `.env` file.
   :::

8. If the BomaRAG app doesn't launch automatically, select the **Open BomaRAG in browser** option to launch the BomaRAG app and start the [application onboarding process](#application-onboarding).
You can also manually navigate to `localhost:3000` in a browser.

   If you provided Google OAuth credentials, you must sign in with Google before you are redirected to your BomaRAG instance.
